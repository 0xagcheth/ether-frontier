# Object Lore and Material Overlay v4

Status: canonical object-direction overlay  
Updated: 2026-07-23

## 1. Назначение

Документ связывает runtime-объекты с lore v4 и визуальными слоями мира.
Он дополняет `object-family-and-variation-spec-v4.md`, но не меняет ID, footprint,
animation contract или технические слоты.

Legacy-описания Grimhold в `asset-prompt-bible.md` не являются визуальным
источником. До полной замены prompt bible данный overlay определяет эпоху,
материалы, знак и запрещённые заимствования каждого объекта.

## 2. Универсальные правила

- true top-down orthographic 90°;
- база сохраняет стабильный footprint;
- движущаяся часть существует отдельным cardboard layer;
- один объект не смешивает все культурные слои;
- основной владелец задаёт 70–85% материального языка;
- вторичный исторический слой занимает не более 15–30%;
- знак не заменяет конструктивное отличие;
- чёрное стекло не кодирует человеческую внешность;
- ни один слой не копирует живой сакральный или экстремистский знак.

## 8. Экономические артели

### `sawmill` — Плотницкая артель

Владелец: Застава и дальневосточный экспедиционный слой.

Модули: рабочее основание, штабель, козлы, пила/резак, стружка, ростовой маркер.
Не изображать промышленный западный sawmill или декоративную деревню.

### `quarry` — Каменная артель

Владелец: Застава поверх погребённого даарийского слоя.

Модули: низкая рабочая площадка, отдельные плиты, ворот, канат, инструмент,
пылевой слой. Найденный камень показывает медное русло или водяной след, но не
покрывается ковром псевдорун.

## 9. Стратегические объекты

### `castle` — Китеж-17

Главный материальный коллаж мира:

- советская архивная рамка;
- древняя деревянная клеть;
- даарийские четыре русла;
- один затопленный антланский фрагмент;
- отдельные кабели, ворота, прожектор, антенна и сигнальные слои.

Он не является средневековым замком. Основной силуэт низкий, радиально-секционный
и читаемый сверху.

### `spawn_cave` — Разлом Пекла

Не пещера с фасадным входом. Это горизонтальный разрыв карты из нескольких
несовпадающих контуров:

- земля/камень;
- пустой слой Нави;
- глинистый контур Нижнего города;
- серый слой редакции;
- отдельные пульсирующие швы.

Каждый источник волны может менять верхние overlay-модули без изменения
основного footprint.

## 11. Обычные враги

### Нижний город

`fast`, `warrior`, `brute`, `raider`, `berserker`, `shield`, `tunneler`,
`spider`, `air` используют глину, кость, тёмное дерево, панцирь и старые
даарийские крепления. Они различаются функцией тела и снаряжения, а не одной
перекраской.

### Серые

`witch_doc`, `bomber`, `spellbreak`, `scout` используют белёсую керамику,
сменные линзы и удалённые имена. Линза, створки, карточки управления, зарядные
контейнеры и interference frame — отдельные слои.

### Повреждённая Навь

`slime`, `necro`, `summoner`, `golem`, `wraith` используют неполный двойной
контур, отсутствующий центр и дымчатые бумажные формы. Свечение находится на
отдельном слое.

### Машины

`machine`, `iron_jug` имеют основную конструкцию Китежа. Владельческий overlay
определяет захват:

- Серые: белёсая керамика и линза;
- Антлань: латунное кольцо, бирюзовая панель, соль;
- Лига: съёмная гиря, долговая лента, двойное крепление.

Overlay не может менять машину в неузнаваемый объект без нового ID.

## 14. Варианты владельца

Owner overlay допускается только для сюжетно захваченных сущностей.

Обязательные поля будущего manifest:

- `baseEntityId`;
- `ownerOverlayId`;
- `ownerLayerSlots`;
- `ownerPaletteRole`;
- `removableOnLiberation`;
- `drawOrder`;
- `attachments`.

Примеры:

- `machine + grey_capture`;
- `machine + antlan_drowned`;
- `machine + league_debt`;
- `iron_jug + grey_capture`;
- `bossMachine + fatta_ring`.

## 15. Производственный порядок

1. Утвердить нейтральный material/projection baseline.
2. Собрать `watchtower` как эталон Заставы.
3. Проверить runtime atlas, manifest, review grid и composite.
4. Проходить объекты по порядку `object-family-and-variation-spec-v4.md`.
5. Для каждого объекта сначала фиксировать владельца и культурный слой из этой
   таблицы.
6. Не переходить дальше без visual + technical validation.

Этот документ не отменяет текущую блокировку: до утверждения material baseline
производство Watchtower не начинается.
